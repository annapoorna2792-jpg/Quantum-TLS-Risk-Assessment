The scoring model

In plain terms: three things decide the score — how the keys are exchanged, how the certificate is signed, and how long the data must stay secret. A penalty is added where the connection has no forward secrecy.

Factor 1 — Key exchange

Shor's algorithm recovers session keys from a recorded classical handshake.

Factor 2 — Certificate

A forged certificate allows impersonation regardless of key exchange.

Factor 3 — Data lifetime

Retention determines whether the data still matters when the threat arrives.

25y+ policy records25
15y loan files / PII22
8y payment / securities18
< 8y10

Penalty — Static RSA accepted (+10)

A session negotiated without forward secrecy is recoverable from the server's long-term key. One key compromise exposes every recorded session, not just one.

Stated limitation. These weights are a risk model, not an empirical result. They encode a judgement that key exchange and certificate signature are of comparable severity and that data lifetime modulates rather than dominates. An institution should substitute its own weights. What the engine contributes is that every input is measured rather than assumed.

Findings

In plain terms: what the scores reveal once every endpoint is measured.

Confidentiality is widely protected. Authentication is not.

61% of endpoints negotiate hybrid ML-KEM, so recorded sessions resist decryption. 0 present a post-quantum certificate. Every endpoint remains forgeable by a quantum adversary — a Web PKI constraint, not an institutional failing.

Readiness is inherited, not engineered

Endpoints behind a major CDN were post-quantum capable in 83.3% of cases against 44.8% origin-served — a risk difference of 38.5 points, Fisher exact p = 0.00499. Institutions that self-host are the migration priority.

API endpoints score worse than web endpoints

In nine paired institutions, no API endpoint was more post-quantum capable than its own website, and none was less likely to accept static RSA. API traffic is not cacheable, so it bypasses the CDN and never inherits its defaults. Assessing a vendor's public site systematically overstates the integration channel.

Retention cannot be reduced enough to help

Under institution-typical retention no endpoint escapes exposure on retention grounds. Only at the bare regulatory minimum do most drop to low urgency — and insurance policy records, at a 10-year floor, still do not. Cryptographic migration is the only available control.

How the engine works

In plain terms: from a TLS handshake to a ranked migration list, in five steps.

TLS handshake probe→ Parameter capture→ 3-factor score→ HNDL exposure→ Priority queue

Step 1 — Measure, don't infer

A ClientHello is sent offering only X25519MLKEM768 with an empty key_share. Under RFC 8446, a server supporting it must reply HelloRetryRequest naming that group. No ML-KEM implementation is needed on the client — the engine observes which group the server asks for.

This replaced an earlier scan whose post-quantum column was inferred from the CDN. That scan produced an impossible result — an endpoint recorded as negotiating hybrid key exchange without TLS 1.3 — which is what prompted the rebuild.

Step 2 — Validate the instrument

Cloudflare and Google are probed as positive controls, both publicly documented as supporting X25519MLKEM768; both return capable.

Zero impossible states occurred across all probes. The static RSA finding was cross-validated against OpenSSL 3.0.13 as an independent implementation. The post-quantum finding could not be — OpenSSL 3.0.13 has no ML-KEM — and that is stated as a limitation rather than claimed as corroboration.

Step 3 — Classify outcomes honestly

Every probe is classified measured, tls12_only, non_response or host_down. TLS 1.2-only hosts are measured negatives and stay in the denominator — a server refusing TLS 1.3 cannot negotiate hybrid key exchange. Non-responses are measurement failures and are excluded, named, and reported.

Step 4 — Score and prioritise

The three factors combine into a 0–100 score. Sorting by score gives a migration order that reflects both cryptographic weakness and data lifetime — so a strong endpoint holding 25-year policy records can outrank a weak endpoint holding short-lived data.
